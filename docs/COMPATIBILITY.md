# CloudSIP Compatibility Guide

CloudSIP 1.0.0 is a static WebRTC SIP client for Asterisk-compatible PBX systems. It connects directly from the browser to SIP over secure WebSocket and does not require a CloudSIP backend.

## Default compatibility profile

Use PJSIP, secure WebSocket, DTLS-SRTP, ICE, Opus and G.711. Keep SIP session timers enabled. Add STUN or TURN only when direct ICE connectivity is not reliable.

## Platform matrix

| Platform | Recommended baseline | Integration path | Notes |
|---|---|---|---|
| Asterisk | Supported LTS release | Native PJSIP endpoint and WSS transport | Default and most direct setup |
| FreePBX | Current release using a supported Asterisk version | PJSIP extension with WebRTC enabled | Use custom configuration only for settings not exposed by the GUI |
| Issabel | Release using an Asterisk version with PJSIP WebRTC support | PJSIP endpoint and HTTPS/WSS services | Verify bundled Asterisk and certificate versions before deployment |
| VitalPBX | Current release using a supported Asterisk version | PJSIP device with WebRTC and WSS enabled | Confirm firewall and NAT rules generated by the PBX |

Compatibility depends on the bundled Asterisk version and PBX configuration, not only the distribution name.

## Required PBX capabilities

- A reachable `wss://` SIP WebSocket endpoint with a trusted TLS certificate.
- A PJSIP endpoint configured for WebRTC media.
- DTLS-SRTP and ICE enabled for the endpoint.
- Browser-compatible codecs, preferably Opus and G.711 μ-law/A-law.
- RTP and ICE traffic permitted by the firewall and NAT configuration.
- Correct public and local network definitions in Asterisk.

## Recommended PJSIP endpoint profile

The exact file and section names vary between platforms. The endpoint should resolve to settings equivalent to:

```ini
[webrtc-user]
type=endpoint
transport=transport-wss
context=from-internal
disallow=all
allow=opus,ulaw,alaw
webrtc=yes
direct_media=no
rtcp_mux=yes
ice_support=yes
media_encryption=dtls
dtls_verify=fingerprint
dtls_setup=actpass
use_avpf=yes
```

Authentication and AOR sections remain specific to the extension and PBX. Do not copy credentials into documentation or source control.

## CloudSIP settings

| Setting | Default | Alternative preference |
|---|---|---|
| WSS | `wss://pbx.example.com:8089/ws` | Custom TLS port and path |
| Session timers | Enabled | Disable only for a confirmed PBX interoperability issue |
| ICE servers | None | Add STUN, then TURN when required |
| Codec policy | PBX offers Opus/G.711 | Restrict codecs at the PBX when necessary |
| Number rules | Number unchanged | Configure dial-plan transformations locally |

## Validation checklist

1. Open the Asterisk HTTP status page or CLI and confirm HTTPS/WebSocket is active.
2. Confirm the browser trusts the WSS certificate without an exception page.
3. Register one dedicated WebRTC extension in CloudSIP.
4. Test outbound, inbound, answer, hangup, mute, hold and DTMF.
5. Check ICE diagnostics and confirm the selected candidate type.
6. Test both directions of audio from an external network.
7. Test transfer, conference and call waiting only after basic calling is stable.

## Common failures

| Symptom | Check first |
|---|---|
| WSS connection fails | Certificate chain, WebSocket service, port and reverse proxy upgrade headers |
| SIP registers but no audio | RTP firewall, NAT addresses, ICE candidates and DTLS certificate |
| One-way audio | Incorrect external media address or blocked RTP/ICE path |
| Calls fail after answer | Codec overlap and DTLS-SRTP negotiation |
| DTMF is not received | RFC 4733 telephone-event support and endpoint mode |
| Registration drops after sleep | Network recovery status and session timer compatibility |

## Support boundary

CloudSIP controls the browser-side SIP/WebRTC client. PBX dial plans, trunks, certificates, NAT, firewall rules, codecs and distribution-specific GUI behavior remain part of the PBX deployment.
